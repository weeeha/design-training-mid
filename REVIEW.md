# Чек-лист разбора

По нему разбирается каждая сданная задача. Удобно и для самопроверки.

## 1. Понял ли проблему

- [ ] Может своими словами объяснить, что сейчас сломано и для кого.
- [ ] Использовал данные из брифа (цифры, прайс, ответы), а не только картинки.
- [ ] Заметил ограничения и не нарушил их.

## 2. Решение

- [ ] Решение отвечает на проблему, а не просто делает экран красивее.
- [ ] Самое важное на экране видно первым.
- [ ] Есть модель или схема там, где она нужна: шаги визарда, модель товара, матрица прав, правила приоритета.
- [ ] Учтены обе стороны или все роли, которые есть в брифе.

## 3. Состояния и краевые случаи

- [ ] Пустое состояние, загрузка, ошибка.
- [ ] Худший день: много данных, длинные названия, всё срочно одновременно.
- [ ] Переходные состояния: черновик, изменение ответа на раннем шаге, закрытый салон и так далее.
- [ ] Состояние, в котором у человека нет прав или данных.

## 4. Качество исполнения

- [ ] Единая сетка, отступы и типографика.
- [ ] Статусы читаются без цвета: есть слово, иконка или позиция.
- [ ] Тексты интерфейса понятные: кнопки говорят, что сделают.
- [ ] Контраст текста достаточный.

## 5. Объяснение

- [ ] Может объяснить каждое ключевое решение и что было альтернативой.
- [ ] Называет, что не успел и что сделал бы дальше.

## Как читать результат

- **Мидл:** уверенно закрыты разделы 1, 2 и 4, в разделе 3 есть основные состояния.
- **Крепкий мидл:** плюс полностью закрыт раздел 3, и краевые случаи найдены самостоятельно, до подсказок.
- **Шаг к сеньору:** сделано задание из блока «Если осталось время», и решения объяснены через бизнес и пользователей, а не через вкус.
